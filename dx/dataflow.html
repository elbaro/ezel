Dataflow ​

Dataflow computing is a software paradigm based on the idea of representing computations as a directed graph, where nodes are computations and data flow along the edges.[1] Dataflow can also be called stream processing or reactive programming.[2]

  • Dataflow - Wikipedia

Design Goal ​

Reactive ​

When the input data is updated, only the affected plots and geometries are rendered again.

Incremental ​

When the input data is updated, only the changes propagate to the final rendering result.
If two or three points are added to a scatter plot containing one million points, dataflow uploads only the new points to the existing GPU buffer.

Explicit ​

The dataflow module doesn't try to auto-detect any change in data by comparing the full snapshot or hash-consing.
The user needs to call the data update API.

Fluent Interface ​

The DAG can be constructed easily through a fluent interface. Each operation derives a new node from its parent nodes.

rust
let series: NumericSeries = ..;

let range = series.ln()?.range()?;

Implementation ​

DBSP ​

We borrow the idea of DBSP[^1] with modifications and extensions:

  • The original DBSP implementation processes data row-by-row. We choose columnar processing so that we can vectorize the operations.
    Changes propagate as column vectors rather than row tuples.
  • The graph is dynamic; nodes can be added or removed. A new node requests an initialization snapshot from its nearest materialized dependency.
  • A node can emit different data shapes: scalars, vectors, or data frames.

^1: DBSP: Automatic Incremental View Maintenance for Rich Query Languages (pdf)

Supported Incremental Operations ​

The following operations support incremental updates:

  • Append { values, max_capacity: Option<u32> }
  • Prepend { values, max_capacity: Option<u32> }
  • TruncateFront(usize)
  • TruncateBack(usize)
  • Patch(Vec<(usize, T)>) — replaces values at the given indices
  • Full { data: Arc<[T]>, is_reset: bool } — replaces the whole column; is_reset controls whether visual row continuity is discarded

Ring ​

A ring buffer supports the operations above.

However, splitting data across two contiguous slices creates several issues:

  • On the CPU, SIMD logic can become complex.
  • On the GPU, multiple ring buffers can wrap at different positions. Each complete buffer—including unused slots—must be passed with its own offset, which is awkward to handle.
