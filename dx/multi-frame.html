Multi Frame ​

The API for multi frame rendering has two requirements:

  • Identity tracking
  • Cache invalidation

Identity tracking ​

This is similar to keyed vs non-keyed js frameworks.

When a Plot is added, removed, or moved, per-Plot UI state should be attached to the correct Plot.

UI state:

  • zoom
  • translation
  • animation velocity and remaining time

We cannot use the following as PlotId:

  • &Plot pointer address
  • Plot.hash() - 2 identically looking Cartesian2D plots will return the same hash. If we include the absolute position in the hash - it's prone to resize.

Option A: holds PlotId in each Plot ​

rust
struct Cartesian2D {
  #[serde(skip)]
  id: PlotId,
}

struct PlotId(usize);

impl Default for PlotId {
  fn default() -> Self {
    PlotId(global_atomic_counter.incr())
  }
}

Option B: keep UI State within Plot ​

rust
struct Cartesian2D {
  state: Cartesian2DState,
}

Cartesian2D {
  state: Default::default(),
}

Since the ui state is locally stored, we don't have to remember the mapping or define PlotId.
When we update the state, and how we update the state is discussed in 'Cache Invalidation'.

Cache Invalidation ​

Cache Invalidation is split into two sub-problems.

  1. How do you detect and invalidate the cache?
  2. When do you recompute the cache?

In any solution, we should not require user to manually invalidate the cache.

Option A: External Cache ​

rust
struct Cartesian2D {
  #[serde(skip)]
  id: PlotId,
}

struct CacheStore {
  render_bundle_cache: HashMap<PlotId, RenderBundle>,
  text_metrics: HashMap<(FontFamily, Size), TextMetrics>,
  ..
}

Detect the cache invalidation by calculating hash each frame.
The original data remains read-only.

Option B: Internal Cache ​

Store various cache within Plot.state.

rust
struct Cartesian2D {
  state: Cartesian2DState,
}
  • Option B1: make fields private, and invalidate on setter, recompute on render
  • Option B2: make fields public, and invalidate on different hash on render
  • Option B3: make fields public, and allow the modification of Plot by requesting it to the CacheStore
rust
// B1
plot.set_x_scale(Scale{..}); // invalidate internally


// B3
cache_store.plot_mut(flattened_index, |p| {
  p.x_axis.title = "..";
}); // invalidate the plot on exit. no fine-grained invalidation

Evaluation Points ​

  • [+] Does the construction API support POJO? (simple API?)
  • [+] Does the update API support POJO? (simple API?)
  • [+] Does the user's Plot object remain read-only? (simple API?)
  • [-] Do we have to calculate the hash each frame even if there is no change? (performant?)
┌─────────────────────────┬────────────────┬─────────────┬────────────────┬──────────────────────┐
│         Option          │ POJO construct │ POJO update │ Plot read-only │ No hash if unchanged │
├─────────────────────────┼────────────────┼─────────────┼────────────────┼──────────────────────┤
│ A (External + PlotId)   │ ✓              │ ✓           │ ✓              │ ✗                    │
├─────────────────────────┼────────────────┼─────────────┼────────────────┼──────────────────────┤
│ B1 (Private + setters)  │ ✗              │ ✗           │ ✗              │ ✓                    │
├─────────────────────────┼────────────────┼─────────────┼────────────────┼──────────────────────┤
│ B2 (Public + hash)      │ ✓              │ ✓           │ ✗              │ ✗                    │
├─────────────────────────┼────────────────┼─────────────┼────────────────┼──────────────────────┤
│ B3 (CacheStore closure) │ ✓              │ ✗           │ ✓              │ ✓                    │
└─────────────────────────┴────────────────┴─────────────┴────────────────┴──────────────────────┘

No option scores all [+].

Decision ​

If we store the hash within Series, we only have finite number of fields to hash each frame.
Expects 1~5 us per frame. Needs to verify this after implementation.

Invalidation Event ​

  • A node is added/removed/reordered in Plot Tree
  • A plot zoom event -> invalidate ComputedScale and tick labels
  • A plot focus event
