LLM Policy ​

1. Policy ​

Contributors are expected to follow the LLM policy of The Rust Programming Language.

In addition, LLMs are allowed in

  • Artworks such as logo and themes, where the output can be checked easily by the maintainer
  • Discovery of useful researches (published papers, performance experiments, HCI demos) with disclosure

The maintainer often adds experimental components with disclosure (see below) and uses an LLM for self-reviewed trivial changes without disclosure.

2. Current Usages ​

Ezel uses LLM in

  • Surveying research papers in Computer Graphics, HCI, Vision Science, etc.
  • Drawing the logo and colorbars for the documentation site
  • Collecting public themes, color schemes and example datasets
  • Experimental Components

3. Experimental Components ​

Ezel does not trust raw AI output. However the designs of some components are not finalized yet. Their current implementations can be thrown away next day. To avoid premature optimization, they are filled with placeholder implementations, and Ezel track which components are experimental.

Example: Font Renderer ​

  • The font renderer was initially hand-written using piet-gpu, which is deprecated now,
  • so it was migrated to vello, which does not provide a batched API,
  • so it was migrated to etagere, which does not support non-orthogonal rotation and realtime zoom,
  • so it was migrated to an mSDF shader, which had suboptimal quality and works well for Latin script but requires a large SDF texture for CJK,
  • so it was migrated to a Slug shader, which works well for most parts but cannot draw a dynamic border size,
  • so it was migrated to mSDF + Slug, which is vibe-coded and is planned to be hand-optimized later.
