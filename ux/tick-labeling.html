Linear Scale ​

Extended Wilkinson is a clear winner.

Log Scale ​

EplusM is a good modern alternative to LogScale.

For both LogScale and EplusMScale, we still have to decide:

  • 10^0, 10^1, 10^2 or 1, 10, 100, 1000, 10000, or 1, 10, 100, 1k, 10k, 100k, 1m or raw 1, 10, 100, 1,000, 10,000, 100,000, ..
  • smaller numbers (0.1, 0.01, 0.001)
  • centered log (0.99, 0.999, 0.9999, 1.0)
  • different log base (1, 2, 4, 8, 16, 32, 64)

Decisions:

  • Use base 10 by default
  • Use scientific for |x|>10^7
  • SI? Scientific? Unit?

Label Formatting ​

scale.format.comma = true;       // incompatible with si
scale.format.si = true;          // incompatible with time unit
scale.format.scientific = 8;     // use 10^x since |x|>=8. 0 means no scientific notation.
scale.format.unit = Unit::Bytes1024

Possible combinations:

  SI | Comma | Scientific
  ------------------------
   O     X         X
   X     x         X
   X     O         X
   X     X         O
   X     O         O

It gets complicated further by

  • irregular units (seconds -> minutes -> hours -> days)
  • nice number generation considering the formatting and centering
  • Easy presets for common cases, such as
    • Bytes1024 (1KiB) IEC - comma=false, scientific=0, custom_units=[('K',1024),('M',1048576),..]
    • Bytes1000 (1KB) SI - si=true, comma=false, scientific=0
    • Duration (1ns, 1us, 1ms, 130ms, 5s, 140s, 2m 5s, 250m, 4h 1m 5s) with min/max units
