Tooltip Design Guidelines ​

  1. Don't cover the data point — tooltips obscuring chart elements was a major complaint (Alcaraz-Martínez 2025)
  2. Close spatial proximity — place tooltip near the element, not in a sidebar (Vaniea 2012, Gestalt principles)
  3. On-demand triggering — users wanted control over when tooltips appear, not just auto-hover (Alcaraz-Martínez 2025)
  4. Show exact data values — users relied on tooltips to read precise numbers (Alcaraz-Martínez 2025)
  5. Allow zoomable/resizable text — important for accessibility (Alcaraz-Martínez 2025)
  6. Explain "why" — for scatter plots, show why points are positioned where they are (Stahnke 2015)

Key Findings for Hover Tooltip Implementation ​

From "Probing Projections" (Stahnke et al. 2015)

Tooltip Content Design (Fig. 2):

  • Show absolute values + standard deviations for each dimension
  • Include graphical representations (mini bar charts showing deviation from mean)
  • Color-code bars: red/blue for positive/negative deviation, saturation for magnitude

Tooltip for Comparisons (Fig. 3):

  • When comparing groups, show MEAN and DENSITY columns
  • Include small density plots inline

User Study Findings:

  • "Tooltips with data details were brought up by all participants throughout all tasks"
  • "Some negatively remarked that the tooltips are not as useful as they could be, because they overlapped the projection area"
  • Data distribution as part of tooltip was used throughout all tasks

From "Enhancing Statistical Chart Accessibility" (Alcaraz-Martínez 2025)

Key Finding:

"Tooltips were highly valued by all users, but their implementation must be improved to avoid covering up significant parts of the charts when displayed."

User Observations (Table 10):

  • Users "constantly uses the tooltips" in accessible version
  • "Hovers the mouse pointer over the bars, triggering the tooltip, and zooms in on the screen to read the data"
  • Users preferred accessible version because of "data labels, hover effects and tooltips"

H16 Visible Focus:

  • When element receives focus, there must be visual indication

Key Requirements ​

  1. Never cover the data point being examined
  2. Show exact values (x, y, label)
  3. Visual focus indicator on the hovered point (highlight/ring)
  4. Support on-demand triggering for accessibility
  5. High contrast solid background

Sourced Claims ​

  1. "Tooltips were highly valued by all users, but their implementation must be improved to avoid covering up significant parts of the charts"
  2. User 6's complaint: "Tooltips are nice, but with a zoom applied they cover [the chart]"
  3. User 8 at 500% zoom: "finds the tooltips bothersome" - they obscure the view
  4. Design recommendations (p.3013):
    • (a) Tooltips should be zoomable
    • (b) Offer tooltips callable on demand (not always auto-triggered)
    • Tooltips should not obscure chart elements
    • Reference: NN/g Nielsen Norman Group tooltip guidelines
  5. Implementation note: "when implementing tooltips, the following considerations should be taken into account: (a) tooltips should [not cover elements]"
