Graph-Agnostic Dataflow ​

API ​

rust
let input = NumericInput::new([1.0, 2.0, 3.0]);
let derived = input.ln().max();

1. Move NodeInterner out of Graph ​

rust
pub struct NodeInterner {
    map: DashMap<NodeKey, NodeId>,
    nodes: papaya::HashMap<NodeId, Box<dyn Node>>,
    next_id: AtomicU64,
}

Nodes are interned upon creation, for example NumericInput::new() is interned on creation.

2. Remove Graph from series and scalar objects ​

rust
struct NumericSeries {
  // graph: .., <- remove this
  slot: ..,
}

3. Add Graph::bind and Bound<T> ​

rust
struct Bound<T> {
    graph: Graph,

impl Bound<NumericSeries> {

rust
impl GraphImpl {
    fn bind(&self, node: &?) -> Result<?, ConvertError> {
        if < node id is already bound to the current graph >{
            return Ok(());
        }


        for parent in parents {
            if <parent is not bound> {
                self.bind(parent); // DFS into parent
            }
        }

        // bind the node
        // initialize the state + cold_update()
        Ok(?)
    }
}

This makes sure the parents are always interned before the children. Also, the NodeId of a parent is always smaller than a child.

4. Integrity in step_all and cold_update() ​

Previously Renderer's NodeInterner keeps a list of nodes, and runs step_all() before render().

In step_all(), all known dataflow nodes are updated.
In render(), newly added dataflow nodes are initialized with cold_update().

In a refactored design, Renderer has no NodeInterner, instead Renderer still has a Map<NodeId, node state> that can provide the node list.

However, already interned nodes that are not bound to the graph, are unknown to the renderer when step_all() runs.
In render(), binding the leaf node will bind itself and its ancestors, and they are all cold_updated()-ed.

5. Update serialization ​

In .save(), make sure to bind all ancestor nodes.

Also currently we natively serialize Theme. However, this can duplicate the serialization of the same Theme behind Arc<>.
There are also other objects whose lifetime is different from Plot, for example we are going to add ColorScale.

This means that the existing graph+plot wouldn't work, and we need a new serialization format design.

Unresolved Issues ​
